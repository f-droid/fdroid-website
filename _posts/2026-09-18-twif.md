### This Week in F-Droid

### TWIF curated on Friday, 18 Sep 2026, Week 38


#### F-Droid core

Thanks to [@linsui](https://gitlab.com/linsui), we've unlocked a new way to add developer signed packages to apps for which we already provide packages signed by us. Historically, we've had two ways to setup reproducible builds. The first way, we host only the upstream package after we verify it to be reproducible. The second way, we get the signature of an upstream package, combine it with our locally built package and if they verify reproducibility, we host both our signed package and the upstream one.

The first path works better when the app is freshly included in F-Droid, so all new installs get the same package. But if we want to switch from the F-Droid version to the upstream signed one via this method,  users need to backup, uninstall, reinstall and restore. We regularly announce such switches in these weekly posts.

The second path allows us to add the upstream package alongside our own, so new users get the new upstream signed one and old users get updates from us as usual. No uninstall, no backups, nothing changes. One issue is that for each new version somebody needs to extract the signature and open a merge request, no metadata autoupdate available _(for now, help welcomed!)_.

The new third path - announced on this post - is a combination of the above two. It adds the upstream signed package alongside ours, like the second path above, but we use it directly. There is no need to extract signatures and metadata auto-updates are available. We keep the upstream package intact, since it needs to verify reproducibility, but we modify our own package with a lower versionCode so they don't conflict.

Packages that are setup like this today:

* [Catima](https://f-droid.org/packages/me.hackerchick.catima/)
* **[Conversations](https://f-droid.org/packages/eu.siacs.conversations)** since this week with update `2.20.3+free`
* **[Shattered Pixel Dungeon](https://f-droid.org/packages/com.shatteredpixel.shatteredpixeldungeon)** since this week with update `4.0.0` _(Huge update by the way, see the developer [post](https://shatteredpixel.com/blog/shattered-pixel-dungeon-v400.html))_
* **[Taler Wallet](https://f-droid.org/packages/net.taler.wallet.fdroid)** since a month ago, updated to `1.6.8` this week

This is not all perfect yet unfortunately as this method kinda "hacks" our metadata structure. We are tracking an [issue](https://gitlab.com/fdroid/fdroidserver/-/work_items/1360) about the way the preferred first installs are offered. The first two methods prioritize upstream packages, this one needs a fix to do so.

For now, we can guide users that want to install these apps for the first time to expand Versions in F-Droid client and install the top most version that is compatible with their devices even if the "suggested" label points to a lower versionCode until we fix it.
